# E15: skill notes taught by an oracle

Nov 16–21, 2026

*First written as a working page; this note is the source of truth from 21 Nov 2026 and adds the results. E15 to E18 share one design (same models, tasks, order, probes and exam), so the four notes read best together: [E16](e16.md) (LoRA), [E17](e17.md) (retrieval), [E18](e18.md) (the final BFCL exam).*

## Goal

E15 tests whether tiny models can learn tool use on the job by writing and revising their own notes, with their weights frozen. It compares models that construct and revise their own skills against fine-tuning (E16).

The judgement comes from an oracle (E13's checker), so E15 measures a ceiling: how far notes can lift each model when the feedback is perfect.

## Protocol

| Part | Setting |
| --- | --- |
| Models | The six from E14, weights frozen: Qwen3-1.7B, LFM2.5-1.2B, Qwen3.5-0.8B, Llama-3.2-1B, Falcon3-1B, Gemma-3-1B |
| Practice ground | E13's practice pool, v3 to v5 pooled: 2,400 tasks on BFCL's own tool classes and simulators, written by Gemini from the tools alone (never from BFCL's questions) |
| Practice split | A fixed file, [split.json](../data/split.json): 1,200 practice tasks (the pool shuffled with seed 15, first 1,200, in that order), 1,200 held out, and 200 of the held-out tasks (67 v3, 67 v4, 66 v5) as the probe set. Shared by E15 to E17 |
| Oracle | BFCL's multi-turn checker against E13's hidden reference answers |
| Notes | Written by the model itself, one short lesson after every task, carried in a system message at the start of every task; merged and trimmed by the model when they pass 600 tokens |
| Note updates | After every task, so the next task reads them; tasks run one after another, as in Dynamic Cheatsheet and ACE's online mode |
| Model runs through | Its own BFCL handler and vLLM (E14's handlers; the two newest models on the newer vLLM stack) |
| Before | E14's floors on BFCL; a frozen pass over the whole pool (2,400 tasks) |
| Hardware | One L4 per model, all of that model's runs sharing one vLLM server |
| Seeds | One (15) for every model. Qwen3-1.7B's extra seeds 16 and 17 were started, then stopped on 17 Nov for consistency (kept in the bucket, not reported) |

## Arms

| Arm | What the model gets after each task |
| --- | --- |
| Frozen | Nothing; no notes (the baseline, over all 2,400 tasks) |
| Oracle teaching | Pass or fail, the checker's reason, and the expected calls |
| Oracle judging | Pass or fail only |

For each practice task: **solve** (prompt = BFCL's system prompt with the tools, the current notes, the task); **feedback** from the oracle as the arm allows; **reflect** (the same model reads its attempt and the feedback and writes one lesson, appended unless it mostly repeats a kept note, by word overlap); **curate** (when the notes pass 600 tokens, the model merges and trims them back under).

A self-judged arm (the model judging itself, no oracle) was left for later: it runs only where oracle judging shows learning, which it did not here.

## Runs

18 runs, one per model and arm, all on 17 Nov: 6 frozen (2,400 tasks each, 8 in parallel), 6 oracle teaching, 6 oracle judging (1,200 tasks each). Time per task with notes: Qwen3-1.7B about 76–79 s, the other models 6–10 s.

## Pilot (16–17 Nov)

Qwen3-1.7B on the first 300 practice tasks, oracle teaching against frozen, same order: 151 solved against 158, within noise, and teaching trailed in the last 100 (42 against 49). The notes showed the pattern seen throughout E15: real lessons ("startEngine before cruise control", "lock the doors before starting the engine") spread into wrong ones ("lock the doors before using travel or trading tools"), and the same generic lesson recurred in different words. The pilot was meant as a gate, but E15's question is which models gain from a basic note technique, not how to make notes work, so the technique was kept as it was for all six models.

## Measures

- **Gain over frozen on practice:** each task's result minus the frozen run's on the same task, over all tasks and the latest 200 (difficulty cancels).
- **Probe curve:** the notes saved every 100 tasks (notes-100.txt to notes-1200.txt), scored afterwards with learning off on the 200 probe tasks ([lab/e15/probe.py](../src/lab/e15/probe.py), [deploy/gcp/run_e15_probe.sh](../src/deploy/gcp/run_e15_probe.sh)). The notes are the run's whole learned state, so a snapshot scored later gives what the run would have scored then. About ±7 points per point on 200 tasks.
- **BFCL exam** with the final notes: see [E18](e18.md).

## Findings

1. **Notes do not help any model.** Every probe curve stays within a couple of points of its start, and the gain over frozen on practice is within noise for every run. The official exam agrees: multi-turn base moves by at most 2 points.
2. **Below the floor, notes cannot help at all.** Llama, Falcon and Gemma pass no practice task, with or without notes; their lessons stay generic ("verify tool documentation before executing tasks").
3. **Notes over-generalise.** A correct lesson about one tool becomes a wrong rule for others (the lock-the-doors example), and the same generic lesson recurs. With a 1B writer, notes drift rather than accumulate skill.
4. **Notes have side effects outside multi-turn.** In the official exam (E18), the same notes in every prompt raised single-turn non-live scores for LFM2.5 (+11) and Qwen3.5 (+16 to +20) but cut them for Llama (−20 to −25) and Gemma (−6 to −14).

## Statistical check (E20)

Tested in [E20](e20.md) (paired McNemar tests, Holm-corrected): no notes run changes the probe (all within ±3, every p > 0.2) or BFCL multi-turn base (all within ±2, every p > 0.4). The single-turn side effects are real: non-live rises for LFM2.5 (+4 to +5) and Qwen3.5 judging (+9) and falls for Llama (−13 to −19) and Gemma teaching (−7), all significant.

## What happened along the way

- **Practice split (17 Nov):** as launched, the split was only a side effect of the code; Qwen3-1.7B's extra seeds drew different tasks. The split was fixed as a file shared by every run and later experiment; the seed-15 runs already matched it.
- **One seed (17 Nov):** extra seeds stopped for consistency with the other models; the rule became: more seeds only where seed 15 shows learning.
- **The three zero-floor models:** checked, not a crash: the same failure types as on BFCL in E14 (no valid call in a turn; for Falcon also inference errors from its short context).
