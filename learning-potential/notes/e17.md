# E17: retrieved experience on the job

Nov 18–21, 2026

*First written as a working page; this note is the source of truth from 21 Nov 2026 and adds the results. Shares its design with [E15](e15.md), [E16](e16.md) and [E18](e18.md).*

## Goal

E17 tests the third way a small on-device model can learn on the job: keep a log of past tasks and show the most similar ones as worked examples, with the weights frozen and nothing summarised (Synapse-style retrieval of past trajectories, the common form of RAG for agents). With E15 (notes the model writes) and E16 (LoRA), it completes the comparison: text the model writes, text it retrieves, and weights.

## Protocol

| Part | Setting |
| --- | --- |
| Models | The six from E14 to E16, weights frozen |
| Practice, held out, probe | E15's fixed split ([lab/e15/split.json](../data/split.json)): the same 1,200 practice tasks in the same order |
| Oracle | E13's checker, as in E15 and E16 |
| Memory | Every finished task logged verbatim: its tool classes, the user's requests and the calls, turn by turn |
| Retrieval | A small embedding model (all-MiniLM-L6-v2, 22M parameters, on the CPU) embeds the user's requests. Only logged tasks with the same set of tool classes are candidates; the closest in meaning come first; up to 3 of them within 1,200 tokens |
| Prompt | The examples go into one system message at the start of the task under a short neutral header ("Earlier tasks with these tools and the calls that completed them:"), where E15's notes go. Calls shown in BFCL's reference form for every model; each model still answers in its own format. Otherwise zero-shot, as in E14 to E16 |
| Before | E14's floors; E15's frozen runs, reused |
| Seeds | One (15) |

## Arms

| Arm | What is logged after each task |
| --- | --- |
| Oracle teaching | Every task, with its expected calls |
| Oracle judging | Only the tasks the model passed, with its own calls |

A third run for Qwen3-1.7B, oracle teaching with a 600-token budget, checks whether its long prompt (its reasoning plus the examples) was the limit.

## Near-copy check (before any run)

Retrieval could copy an almost identical answer and overstate learning, so held-out and probe tasks were compared with the 1,200 practice tasks ([lab/e17/nearcopy.py](../src/lab/e17/nearcopy.py)): the probe tasks' closest practice task has a median cosine similarity of 0.68 (maximum 0.90); 2 of the 200 probe tasks share an exact answer with a practice task; 4% use the same functions in the same order. Low enough to keep the split. A hand check also confirmed that a task never retrieves itself.

## Runs

13 runs (6 models × 2 arms, plus Qwen3-1.7B at 600 tokens), all on one VM per model. Time per task: Qwen3-1.7B about 24 s, the others 4–11 s.

## Measures

As E15: gain over frozen on practice; the probe curve (the memory saved every 100 tasks as memory-<n>.jsonl, scored on the 200 probe tasks with learning off, [deploy/gcp/run_e17_probe.sh](../src/deploy/gcp/run_e17_probe.sh)); the BFCL exam with the final memory ([E18](e18.md)).

## Findings

1. **Retrieval helps the middle models, modestly.** LFM2.5 gains up to 14.5 points on the probe (26 → 40.5 at task 600) and Qwen3.5 up to 13.5; both end a little below their peak as the memory grows. On BFCL's multi-turn base, LFM2.5 goes 9 → 14.5 and Qwen3.5 8.5 → 13.5: smaller than E16's probe gains, but similar to E16 on the official exam, with no side effects on the other categories.
2. **It does nothing for the strongest model.** Qwen3-1.7B stays within noise of its start on the probe (47.5–50 at the end), with 1,200 or 600 tokens; on BFCL it moves −3 to +3.
3. **It cannot help below the floor.** Llama, Falcon and Gemma see correct worked examples for the same tools and still almost never produce a valid call (at most 2% of the probe).
4. **Teaching beats judging** for the middle models, as in E16: logging the expected calls of every task gives more and better examples than logging only the model's own successes.
5. **Retrieval is the cleanest method on the side:** unlike notes (E15) and LoRA (E16), it barely changes the single-turn, live and memory categories, since examples are shown only where tools match.

## Statistical check (E20)

Tested in [E20](e20.md) (paired McNemar tests, Holm-corrected): retrieval's gains are suggestive only. On the probe, LFM2.5 +9.5 (raw p = 0.003) and Qwen3.5 +8 to +8.5 (raw p 0.03); on BFCL multi-turn base, LFM2.5 +5.5 (raw p = 0.02) and Qwen3.5 +4 to +5. None is significant after correction, and none is significantly better than notes. Its lack of side effects holds: no BFCL group changes significantly except LFM2.5's multi-turn (+3.4) and Qwen3-1.7B's memory with the 600-token budget (+5.8).

## What happened along the way

- **Design choices (18 Nov):** an embedding model over BM25 (the more common choice in recent agent-memory work), verbatim logs over summaries (to keep E17 distinct from E15's notes), and zero-shot apart from the retrieved examples.
- **Probes:** run on extra VMs after the practice runs; all 13 probe curves complete (the last, Qwen3-1.7B's three runs, scored 21 Nov).
